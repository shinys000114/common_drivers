# ODROID-C5 / S7D native drivers

This project replaces the tightly coupled Amlogic display and media path with drivers organized around Linux kernel interfaces. The main improvements are:

- **Kernel-style organization:** separate DRM/KMS, HDMI bridge, CEC, audio, V4L2 codec, GE2D, GPU and hardware-resource drivers with explicit responsibilities.
- **Hierarchical resource management:** describe clocks, resets, power domains and PHYs in Device Tree and connect drivers through standard provider/consumer interfaces.
- **Standard display, media and audio APIs:** use DRM/KMS, stateful V4L2 mem2mem codecs, DMA-BUF and dma-heap, ASoC/hdmi-codec and the CEC framework in place of vendor-specific display and media controls; the Mali-G310 runs on a Panthor backport with Mesa by default, and the vendor kbase/libMali stack stays selectable.
- **Linux-controlled modesetting:** select and program display timings through DRM instead of relying on U-Boot `outputmode` strings or a vendor timing-name whitelist.
- **Monitor replacement:** handle HDMI hotplug and refresh EDID/modes when a panel changes; repeated hotplug, a sink EDID swapped during deep suspend and SCDC recovery after a sink power cycle are board-verified.
- **Native EDID discovery:** read supported monitor timings directly without routine EDID injection or panel-specific overrides; malformed or missing EDID can still require an override.
- **Streamlined initialization:** make display setup explicit and avoid unnecessary reinitialization; any boot-time improvement remains unquantified by a controlled vendor/native comparison.

Firmware/SMC services are still required: secure HDMI register access, BL31 switching the shared VPU/HDMI power domain, VPU SRAM that firmware has already powered, and codec firmware loaded through the TEE. The display and HDMI drivers reprogram everything after the deep-suspend power cut and start without U-Boot display setup in an emulated cold start; seamless U-Boot logo handoff is not implemented.

## Audience and goals

- Learn how Linux kernel display drivers and their hardware resources fit together.
- Use and improve ODROID-C5 display support through standard Linux interfaces.
- Explore the Amlogic S7D graphics, display and media architecture.

## Tested displays

- AlphaScan AOC 2269WM
- LG HDR 4K 27UK600
- Hardkernel ODROID VU7A+
- Hardkernel ODROID VU7+
- Hardkernel ODROID VU5A
- Hardkernel ODROID VU12

The bench also has an ANI-4KANA HDMI analyzer, which reports the received timing, InfoFrames, SCDC state and audio packets and can emulate sink EDIDs.

Automated validation also uses DRM writeback and headless KMS, with host-side virtual HDMI sink tests. Headless capture exercises the real S7D VPU without a connected monitor; virtual sink tests check negotiation and calculation paths. The analyzer checks what is physically transmitted on HDMI; none of these judges a monitor's rendering or picture quality.

## Runtime requirements

The verified results assume the following build, userspace and boot configuration. Apart from the Kconfig and DT defaults named below, none of it is shipped in this repository.

- **Kernel configuration:** the S7D decoder option now builds HEVC, VP9, AV1 and the JPEG encoder by default beside H.264 (69b8d13aa; the `VIDEO_AMLOGIC_S7D_{HEVC,VP9,AV1,JPEG}_EXPERIMENTAL` symbols keep their names). The kernel repo's `odroidc5_defconfig` builds the decoder (`VIDEO_AMLOGIC_S7D=m`) and GE2D (`VIDEO_S7D_GE2D=m`) modules and chooses the Panthor side of the ODROID-C5 GPU choice with `DRM_S7D_PANTHOR=m` (fba8e3eaf; kernel repo claude/c5-native-next f3f8a91db3ba, "config: build Panthor as the default GPU driver"). A host `olddefconfig` of the committed defconfig resolves to these symbols, but no kernel built from it has been booted; the bench kernels #525 and #526 come from a separate build configuration with the same GPU and codec choices. The choice builds either Panthor or kbase, so a selectable kbase module has to come from a second configuration with `AMLOGIC_C5_GPU_KBASE`.
- **Video firmware:** `video/video_ucode.bin` and the `optee-amlogic` package from the board's PPA (TA and tee-supplicant). When the native driver loads the archive first, the vendor preload service (`videoFirmwarePreload.service`, `tee_preload_fw`) stops as failed after five restarts; this is harmless.
- **GPU:** linux-firmware with `arm/mali/arch10.12/mali_csffw.bin` and Mesa 26 or later for Panthor (the bench runs Mesa 26.2.6 from the kisak PPA). When modules from both GPU configurations are installed, a `modprobe.d` blacklist of `mali_kbase` or `panthor` selects the stack at boot. On Panthor boots, the libMali package's Arm WSI Vulkan layer must be disabled with `DISABLE_WSI_LAYER=1`, set through a systemd user-environment generator. OpenCL on Panthor uses the distro `mesa-opencl-icd` (rusticl) with `RUSTICL_ENABLE=panfrost`.
- **Graphics heap:** `gfx-heap-size=320` in `/boot/config.ini`. U-Boot sizes `heap-gfx` from it, and 180 MB was too small for Chromium 4K buffers. Without the setting, the DT default now also gives 320 MB (5f9530e74; it was 48 MB). The bench always sets the value, so that default has not been checked on the board.
- **Display:** the verified runs set `s7d_drm.primary_afbc=0` in `/etc/modprobe.d`, so that fullscreen video can scan out directly under GNOME. At claude/c-int this is the default (da36a3d79), so the line can be dropped, but no boot without it has been run.
- **GNOME session:** `MUTTER_DEBUG_PAINT=ignore-color-state-for-direct-scanout` and `GSK_GPU_DISABLE=mipmap` in `/etc/environment.d`. GTK video players also need `GDK_DEBUG=color-mgmt` for fullscreen offload, and square window corners (`window, window.background, .csd { border-radius: 0; }` in `gtk.css`) for windowed offload.
- **Chromium:** a deb build of upstream Chromium (not the vendor PPA package and not a snap) started with `--enable-features=AcceleratedVideoDecoder,PreferV4L2VideoAcceleration,AcceleratedVideoDecodeLinuxGL --ignore-gpu-blocklist --password-store=basic`.
- **Memory:** zram swap through `systemd-zram-generator` (zstd, half of RAM) plus a sysctl file (swappiness 180, page-cluster 0); the board has no other swap.

## Feature coverage

### Functionality in scope

The goal is every feature the S7D hardware supports, including blocks that the C5 vendor profile disables, apart from the items under Out of scope. Not all of them are implemented yet; the table below records native support and remaining work.

- HDMI display output through DRM/KMS, progressive and interlaced, RGB and YCbCr up to 12 bits, with HDR10/HLG signalling, and internal VPU capture through standard DRM writeback.
- Four-input composition: two OSD planes and two video planes with scalers, color matrices, gamma and the VPP picture-processing blocks.
- Graphics AFBC and AFRC scanout through the Mali AFBCD and GFCD backends, and the separate Amlogic compressed-video FBC path.
- H.264, HEVC, VP9 and AV1 decoding.
- MPEG-1/2, MPEG-4, VC-1/WMV, AVS/AVS2, MJPEG/JPEG decoding and MVC.
- H.264 and JPEG encoding, and concurrent decode and encode sessions as the datasheet lists them.
- GE2D color conversion, scaling, rotation and alpha blending. The native V4L2 mem2mem driver is an optional module outside the default video path, and blending has no V4L2 interface.
- Mali-G310 3D rendering and OpenCL compute through Panthor + Mesa (default) or the vendor kbase + libMali.
- Audio output through ASoC: HDMI (L-PCM up to 8 channels and 192kHz, compressed passthrough), analog line out, SPDIF and 40-pin I2S.
- CEC, including TV remote keys as input events and wake from the TV: through the AOCPU from deep suspend and power-off, and through the CEC controller in s2idle.
- System sleep (s2idle, deep suspend, poweroff) with full restoration of the display, HDMI, audio, media and GPU blocks.

### Experimental or incomplete capabilities

These capabilities are implemented but only partly qualified. Limited use, internal checks, source/build checks or a successful subset of tests do not establish complete support.

- AFRC scanout: implemented on GFCD and offered only with `s7d_drm.primary_afbc=1`, but no producer allocates AFRC buffers, so only host model tests have run.
- JPEG encoding: built by default since 69b8d13aa and limited to 1080p 4:2:0 from NV12/NV21. The last encode runs (including one during a 4K HEVC decode) used a module without the four JPEG changes on claude/c-int (session staging buffers, scan check, firmware once per lease, DMABUF import), which have passed only v4l2-compliance 48/48 (impl (69)).
- Interlaced output: 1080i/480i/576i checked on the analyzer, in registers and through writeback, not on a monitor; linear OSD planes only.
- 40-pin I2S output: TDMIN loopback passes, and the overlay now programs the audio pad crossbar and MCLK pad 1, but only host checks have run. The overlay was not enabled on the board, and the header output (data, clocks and MCLK on pin 7) is unmeasured.
- HDMI and SPDIF compressed passthrough (IEC 61937): implemented, with IEC958 controls on hw:0,0, hw:0,1 and hw:0,3, but no compressed stream has been played, because the bench monitor lists L-PCM only and the analyzer was not connected. HBR is not implemented.
- Refresh rates above 60Hz: FHD120 is verified through writeback only; no bench sink runs above 60Hz.
- Desktop video on the kbase/libMali stack: stock GNOME needs a mutter patch for it; Panthor is the verified desktop stack.
- Panthor system suspend/resume: one s2idle cycle and six deep cycles with GNOME resumed, and the deep cycles logged no Panthor errors. The planned repeated cycles, with a GPU test after each, have not run.
- Several decoder sessions on one engine: with M1 (claude/m-multi ffd47616e, "media: run up to four sessions on the HEVC core") the HEVC core takes up to four HEVC, VP9 and AV1 sessions, bit-exact at 1080p30 on the board. On VDEC, the first M3 series (claude/m3probe b03890b16, "media: run up to four H.264 sessions on VDEC") lost or blocked sessions. Its revision on claude/m-multi, which adds 97c4fae90 ("media: acknowledge the H.264 configuration first"), decoded two H.264 sessions bit-exact in 5/5 runs and four in 3/3 runs at 1080p30 on #526, and a stopped H.264 player no longer held up the others (impl (69)). claude/c-int keeps one H.264 session. Build #527 carries the series and passed the same tests on the board (see Latest verified baseline); Stage B2 was stopped after its review, so the app multi-window checks and the 4K60 speed comparison were not rerun on the final module (impl (69)).
- Decoder coding tools added on 2026-11-04 and not yet run on the board: H.264 pic_order_cnt_type 1, frame_num gaps, recovery-point resume, same-size SPS changes and levels 6.x; HEVC several slices, dependent slice segments, tiles, long-term references and temporal sub-layers; VP9 render sizes that differ from the frame size and show-existing frames from their own buffer; AV1 film grain (decoded without the grain), resolution changes at key frames and key-frame start.
- GE2D BT.2020 conversion, full-range reporting of RGB from YUV, the streaming selection and 16× checks, and the multi-planar node for NV12M/NV21M sources: v4l2-compliance 48/48 only (impl (69)).
- Plane changes at vblank: the rewritten VD1 scaler write list (666c06fe9), VD2 start, stop and rescale, linear OSD rescale and four-input rerouting (c9c4ec9a0, b97a52ee8, 75fb0fc1d), and the zpos layout that gives compositors underlay planes (45c0c1dde) are build only: #526 carries them, but no test exercised them.
- CEC: transmit was checked against a monitor without CEC. Receive, TV remote keys and TV wake from s2idle, deep suspend and power-off are build only, because the bench has no CEC TV.

### Out of scope

- CVBS output.
- HDMI video or audio input, including eARC reception.
- HDCP and protected content (TVP), Dolby Vision and other proprietary HDR formats.
- HDMI FRL and DSC: S7D transmits TMDS only, up to 600MHz.
- Microphone / PDM input: not wired on ODROID-C5.
- Unused board interfaces without an accessible connection on ODROID-C5.
- 12-bit writeback capture, a hardware limit (S7D VDIN1 stores 8 or 10 bits), and end-to-end 12-bit precision qualification, which this bench cannot measure; 12-bit HDMI transport is a separate capability.
- Stateless (request API) V4L2 decoding: the S7D firmware parses the bitstream; all codecs are exposed as stateful decoders.
- Vendor media APIs (amstream, amvideo, codec_mm and the userspace built on them): the native drivers expose standard V4L2 codecs and DRM planes instead.
- Plane features on interlaced output (AFBC/GFCD primaries and the video planes), closed by decision on 2026-10-31.
- Windowed and maximized video beyond the GPU composition rate: fullscreen video at 60fps is the target, and windowed video is composited by the GPU.
- Application source patches (mutter MPO and external dma-buf import, the GTK 4.22 FBO backport, Chromium overlay delegation): tried as experiments and kept as references only; they are neither shipped nor required.

### Known limitations

These come from userspace, applications, the platform or the bench rather than from missing driver features:

- Direct scanout stops while anything covers the fullscreen window: Ubuntu Dock intellihide while the dock is shown, GNOME "Low Disk Space" or crash-report banners, a pointer tooltip left over the video, or Chromium's keyring prompt (avoided with `--password-store=basic`).
- VLC 3 draws video with its own GL renderer, so it is never scanned out directly. FFmpeg-based players (VLC, mpv) copy every decoded frame, because FFmpeg's v4l2m2m decoder has no DRM PRIME output. FFmpeg's 4K CPU copy peaks at about 57fps (11ee15db1), so mpv with v4l2m2m-copy is expected to fall short of 4K60; mpv itself, including `--vo=dmabuf-wayland`, has not been run on the board. FFmpeg 8.0 also has no `av1_v4l2m2m`, so these players decode AV1 in software. GStreamer players such as Showtime use the zero-copy path.
- Generic players get 8-bit NV12 for 10-bit/HDR streams; 10-bit reaches the display only through the Amlogic FBC formats.
- On a kbase/libMali boot, GTK video offload freezes with stock mutter (libMali has no GR88); `GDK_DISABLE=offload` avoids it at about 11fps for a 4K window.
- GNOME's HDR mode was checked on the kbase/libMali stack only. The primary plane offers 10-bit RGB only as linear ABGR/XBGR2101010 (no XRGB2101010 and no 10-bit AFBC), and PQ/HLG video scanned out directly with `MUTTER_DEBUG_PAINT` set gets no tone mapping on an SDR desktop; neither has been judged on a monitor yet.
- Reloading s7d-vdec moves the `/dev/videoN` numbers, and the second GE2D node moved the decoder to `/dev/video2` on #526, so clear the GStreamer registry (`~/.cache/gstreamer-1.0/registry.*.bin`) afterwards; reloading s7d-drm on a Panthor boot renumbers `card0` to `card1`.
- No long soak (an hour of 4K60 decode, display and GPU load) or combined worst-case memory run has been done. The longest decoder stress is a 6-minute soak on 2026-11-04 with the s7d-vdec module from claude/fix-hunt e3533600e ("media: keep a decoder waiting for its first header pollable"): 12 rounds of `v4l2-compliance -s` on the decoder, each followed by four concurrent 1080p decodes (VP9, VP9 with resolution changes, AV1 and H.264). All 48 decodes were bit-exact (impl (69)).
- A client that sets the primary plane's zpos gets -EINVAL, as on amdgpu (45c0c1dde). The C5 mutter underlay port and the local underlay test tools must leave it alone and place a video plane below 3 for an underlay or above 3 for an overlay.
- PipeWire offers a single HDMI stereo sink ("Built-in Audio Stereo", hw:0,0) through its fallback mapping. No UCM2 profile for the card (driver `axg-sound-card`, card AML-AUGESOUND) is installed, so GNOME does not offer the line out, SPDIF, multichannel HDMI or passthrough. A local profile has only been parsed on the host.
- After a kernel-panic warm reboot, eth0 once came up without its PHY (`__stmmac_open: Cannot attach to PHY (error: -19)`) and stayed down until a full power cycle. Other panic reboots the same day came back with networking (impl (69)). This is in the meson8b-dwmac/stmmac path, outside the native drivers.
- The vendor memory-debug DMC monitor sometimes logs `DMC0 SEC READ CHECK ERROR ... port:ARM_A53` for an address inside the `linux,secmon` reserved region. It logged this twice on 2026-11-04, and the same message is in 2026-10-12 and 2026-10-19 logs, so it is treated as pre-existing. Nothing failed after it, and the reader and the cause are unknown (impl (69)).
- Booting build #526 with `slub_debug=FZPU` panicked in the sound card bind on every attempt: `snd_soc_add_pcm_runtimes()` faults at 0xcccccccccccccccc, and the panic report points at the link array that `meson_card_reallocate_links()` grows with `krealloc(__GFP_ZERO)`. Source reading attributes this to how Linux 6.12 krealloc handles red-zone bytes when it grows an object in place, but that was not proven on the board, so boot without `slub_debug` while the card is loaded (impl (69)).

The native drivers follow the selected S7D vendor implementation unless the hardware documentation or board validation supports a different choice. The table records intentional configuration and structural differences; missing native features are listed in the status table above.
